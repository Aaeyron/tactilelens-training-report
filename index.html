Source and licence

im2latex-100k (Deng et al., 2017), Hugging Face copy yuntian-deng/im2latex-100k. Licence: CC0-1.0 (public domain dedication), as stated in the dataset README. Formulas taken from arXiv physics papers and rendered to images with LaTeX; published splits train 55,033 / val 6,072 / test 6,810.

Filter rules

Applied in this order; a formula is dropped at the first rule it fails.

  1. At most 60 LaTeX tokens.
  2. Only commands from an allowed list: fractions, roots, \cdot, \times, \div, \pm, comparisons, \left / \right, spacing, \pi, \alpha, \beta, \theta, \mathrm, \text. No environments, sums, integrals, limits, fonts, accents or matrices.
  3. Subscripts only as a letter with a number (x_1, x_{2}).
  4. Braces nested at most 3 deep.
  5. No words of 4 or more letters (that is text, not a formula).
  6. Contains at least one of =, <, >, \le, \ge, \neq, a power, \frac, \sqrt, f(x).

Then a leak guard between the splits: a training or validation formula is removed when the same image (byte-identical) or the same LaTeX (spaces ignored) is in the test split, and a training formula also when it is in the validation split.

Limits

  • The formulas come from physics papers and pass the filter on syntax; they are not worksheet algebra (for example F ^ { 2 } - 1 \le 2 ( N ^ { 2 } - 1 ) + ...).
  • The filter checks syntax only: some kept items are fragments or junk (kept example T ( z ) =; removed duplicate 1 is a row of = signs).
  • Printed and cleanly rendered; no phone photos, no handwriting.
  • Topics are assigned by a rule and were not checked by hand; each formula has one topic.
  • The subset is small: 945 / 104 / 120.
  • The base model (PP-FormulaNet_plus-S) was very likely trained on data from the same sources, so the test split is not an unseen test.

What changed during fine-tuning (follow-up run)

The follow-up run's best checkpoint (epoch 3) against the official checkpoint the app ships. Read-only: nothing was retrained, and the test split was not scored again; the examples and error types use the predictions saved when the run was scored. Confidence was measured on the 104 validation formulas, which also chose the checkpoint, so the fine-tuned model's numbers there are on the kind side.

Which parts of the model moved

Each number is how far a part's weights moved, as a share of their size. Overall the weights moved 0.95%: a light touch. The most change was in image encoder: stage 4 (2.20%); of the parts that moved, the least in text decoder: final norm (0.147%). A bigger number shows where training pushed, not how much that part matters for accuracy.

Exactly 0% means not a single weight changed: image encoder: output layers are not on the formula model's path (it reads the image features before them), so training never reached them.

The image encoder also keeps running averages of the images it sees (batch-norm statistics). These moved more, 4.6% to 9.8% per stage: the im2latex images look different from what the model saw before. They are not learned weights and are left out of the numbers above.

Output tokens: 167 of the 50,000 tokens the model can write occur in the training labels. Their output weights moved a median 0.877%, about 2.0 times as much as the tokens that never occur (0.444%). The tokens that moved most, in share of their size, are mostly pieces of commands and words that never occur in the labels: displaystyle, small, smash, −, cent, ensuremath, allow, hfill, ’, kip. Neither model wrote any of them in the 120 test readings, so that change has no effect we can see there.

How sure the model is

For every symbol it writes, the model gives a probability. The weakest symbol's probability is a simple confidence score for a whole reading. If wrong readings score clearly lower than right ones, the app could one day ask the student to re-scan when the score is low; that is not built.

Check: these readings are strictly right for 41/104 (original) and 54/104 (fine-tuned), the same as the counts logged during training (41 and 54), so the measurement uses the same model and preprocessing. The table counts spacing-normalized right.

Online vs offline model on the same test formulas

The app has two formula readers. Offline: PP-FormulaNet_plus-S, the small model that runs on the phone (the shipped model, not the fine-tuned one). Online: PaddleOCR-VL-1.6, the large vision-language model the online pipeline uses, run here on the laptop's GPU with the formula prompt on each cropped image (no layout detection). Both read the same 120 im2latex test formulas; the online model was scored on them once. No training, no app changes.

Agreement as a review signal

Idea: when the phone is online, read each formula with both models; if the two readings agree, trust the offline reading; if they differ, ask the student to check it. Measured on the same 120 test formulas from the saved readings (no new runs). Agree and right are both spacing-normalized. Not built in the app.

88/120readings agree (73%)

19 of 36offline errors a disagree flag catches

A “flag when they disagree” rule would flag 32 of 120 readings. It catches 19 of the offline model's 36 wrong readings and misses 17: those are cases where both models made the same mistake. It also flags 13 of the 84 right offline readings, where the online model was the one that was wrong. When they disagree, the online reading is right 13 times of 32.
